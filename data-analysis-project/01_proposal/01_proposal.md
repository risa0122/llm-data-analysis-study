# 1차 데이터분석 프로젝트 기획

## 1. 프로젝트 제목

**보험계약 이탈 위험 분석과 유지관리 우선순위 탐색**  
공개 건강보험 데이터를 활용한 생명보험 해지·실효 방지 연구의 예비 분석

개인 프로젝트 · 작성일: 2026년 10월 4일

## 2. 프로젝트 배경 및 목적

생명보험 계약의 해지·실효 방지 업무와 논문 주제에 연결할 수 있는 분석을 진행하고자 한다. 관심 있는 문제는 이탈 가능성이 높은 고객을 미리 파악하고, 한정된 유지관리 자원을 어떤 대상에게 우선 배분할지 판단하는 것이다.

현재 분석에 사용할 수 있는 회사 데이터는 없다. 따라서 실제 보험사의 공개 건강보험 데이터를 이용해 이탈 정의, 시점에 맞는 변수 구성, 예측 검증, 우선순위 평가 과정을 먼저 수행한다. 분석 결과의 활용 대상은 보험 유지관리 담당자이며, 이번 프로젝트에서는 고객 접촉 대상을 검토하는 참고 기준을 제시하고자 한다.

건강보험과 생명보험은 계약·갱신 구조가 다르다. 공개 데이터의 이탈을 국내 생명보험의 해지 또는 실효와 동일하게 해석하지 않는다. 또한 **이탈 위험이 높은 고객과 상담으로 이탈을 막을 수 있는 고객은 다르다.** 개입 이력이 없는 이번 데이터로 상담 효과나 실제 해지 감소율을 추정하지 않는다.

## 3. 핵심 분석 질문

분석 대상은 **기준연도 말에 유지 중인 피보험 관계**로 정한다. 기준연도의 정보로 다음 해 상태를 확인하며, 다음 해 신규 가입자는 본 예측 대상에 포함하지 않는다.

| 질문 | 필요한 데이터 | 확인 방법 |
|---|---|---|
| 1. 기준연도의 가입 기간, 보험료, 상품 유형, 판매 채널에 따라 다음 해 이탈 비율은 어떻게 다른가? | 기준연도 `seniority_insured`, `premium`, `type_product`, `distribution_channel`과 다음 해 `lapse` | 그룹별 건수·이탈 비율과 시각화. 적은 표본의 차이를 과도하게 해석하지 않는다. |
| 2. 기준연도까지 확인 가능한 계약 정보로 다음 해 이탈을 어느 정도 구분할 수 있는가? | 기준연도 계약 특성과 다음 해 이탈 여부 | 로지스틱 회귀와 트리 기반 모델을 비교하고, 이후 연도의 데이터로 검증한다. |
| 3. 전체 대상 중 상위 20%를 우선 검토한다고 가정할 때, 예측 기반 순위는 무작위 선정이나 단순 규칙보다 실제 이탈 대상을 더 많이 포함하는가? | 검증 데이터의 예측 점수·이탈 여부 | Recall@20%, Lift@20%로 비교한다. 실제 상담 성과가 아닌 이탈 대상 포착 성능을 평가한다. |

20%는 실제 회사의 업무량을 의미하지 않는 분석상 가정이다. 10%, 30%에서도 결론이 달라지는지 추가로 확인할 계획이다.

### 확보 결과와 분석 가능성

| 기준연도 → 결과연도 | 기준연도 유지 대상 | 다음 해 상태 연결 | 다음 해 기록 미확인 |
|---|---:|---:|---:|
| 2017 → 2018 | 63,487 | 63,486 | 1 |
| 2018 → 2019 | 59,833 | 59,831 | 2 |

**결과 관찰:** `ID`와 `period` 조합의 중복은 0건이었다. 두 연도 쌍에서 대부분의 유지 대상을 다음 해 기록과 연결할 수 있었다. 일부 지역 관련 변수에는 결측이 존재한다.

**해석과 판단:** 단순한 단면 비교뿐 아니라 이전 연도 정보로 다음 해 상태를 확인하는 분석이 가능하다고 판단했다. 다음 해 기록이 없는 3건은 이탈로 간주하지 않고 결과 미확인으로 분리한다. 종료일의 빈 값 역시 곧바로 오류로 처리하지 않고 변수 정의와 상태를 함께 확인한다. 현재는 확보 가능성을 점검한 단계이며 모델 성능이나 이탈 원인은 아직 확인하지 않았다.

확인 근거: [실행 코드](../docs/check_source_data.py), [확보·구조 점검 결과](../docs/data_feasibility.json), [파일 URL 및 체크섬](../data/source_manifest.json).

### 보안 및 활용 범위

회사명, 실제 고객정보, 사내 시스템 자료를 사용하지 않는다. 공개 자료의 익명 식별자도 재식별에 이용하지 않는다. GitHub에는 코드·출처·집계 결과를 관리하고 원본 개인 단위 자료는 재업로드하지 않는다. 건강서비스 이용·청구 정보와 지역 사회경제 변수는 기본 예측 변수에서 제외해 범위를 좁힌다. 결과는 학습·연구용이며 실제 고객의 보장, 보험료 또는 서비스 제공 여부를 결정하는 데 사용하지 않는다.

## 5. 예상 데이터 구조

한 행은 **피보험 관계 1개의 특정 연도 기록**이다. 동일 계약에 여러 피보험자가 있을 수 있으므로 행 수를 계약 수나 독립적인 고객 수로 해석하지 않는다. `ID_insured`는 계약 내부 순번이어서 단독으로 연결하지 않는다. 계약을 변경한 동일인을 계약 간에 추적할 수 있는지는 별도 확인이 필요하므로, 관계 종료를 보험사 전체에서의 고객 이탈로 단정하지 않는다.

| 역할 | 주요 컬럼 | 사용 계획 |
|---|---|---|
| 연결 키 | `ID`, `ID_policy`, `ID_insured`, `period` | 연도 간 연결·중복 확인·계약 단위 검증에 사용. 예측 변수에서는 제외 |
| 유지·이탈 상태 | `lapse` | 기준연도 `2`인 대상을 선택한 뒤 다음 해 상태를 결과값으로 사용 |
| 가입 기간 | `seniority_insured`, `seniority_policy` | 기준연도 말 시점의 값인지 확인한 뒤 사용 |
| 계약 특성 | `type_policy`, `type_policy_dg`, `type_product`, `distribution_channel`, `new_business` | 상품·계약 유형과 채널 차이 분석 |
| 보험료 | `premium` | 기준연도에 납입된 연간 보험료, 유로 단위. 다음 해 보험료는 예측에 사용하지 않음 |
| 날짜·보장기간 | `date_effect_insured`, `date_lapse_insured`, `date_lapse_policy`, `exposure_time` 등 | 관측 시점과 종료 상태 검증. 미래 종료일·종료연도는 예측 변수에서 제외 |
| 기본 분석 제외 | `gender`, 건강서비스·청구 정보, 지역 사회경제 변수 | 기본 모델에서 제외. 필요 시 연령 등 집단별 성능 차이를 집계 수준에서 점검 |

변수 설명서상 `lapse=1`은 연중 종료, `2`는 유지, `3`은 연말 만기·갱신 시점 종료를 뜻한다. 우선 다음 해 `1` 또는 `3`을 이탈, `2`를 유지로 정의할 계획이다. 2차 단계에서 날짜와 코드의 일치 여부를 확인하고, 연중 종료와 연말 종료를 분리한 결과도 비교한다. **이 구분은 자발적 해지와 미납 실효의 구분이 아니다.**

## 6. 예상 분석 방법

### 전처리와 탐색

1. 연도별 규모, 식별자 중복, 결측, 날짜·자료형, 범주 표기를 확인한다.
2. 종료 상태·종료일의 일치와 연도별 변수 산출 시점을 점검한다. 보험료 0·음수 등 특이값은 임의 삭제하지 않고 의미를 확인한다.
3. 기준연도와 다음 해를 연결하고, 미확인 결과·신규 유입·이탈을 구분한다.
4. 가입 기간·보험료·상품·채널별 다음 해 이탈 비율을 비교한다. 관찰된 연관성을 원인으로 단정하지 않는다.

### 분석과 검증

- **기본 비교:** 무작위 순위와 가입 기간 등 단일 변수로 만든 단순 규칙을 사용한다. 규칙과 방향은 개발 데이터에서 정한다.
- **모델:** 해석하기 쉬운 로지스틱 회귀를 우선 사용하고, 비교 모델은 랜덤 포레스트 1개로 제한한다.
- **시점 분리:** 2017년 정보 → 2018년 결과를 개발 데이터로, 2018년 정보 → 2019년 결과를 최종 평가 데이터로 구성한다. 개발 데이터 내부에서는 `ID_policy` 단위로 묶어 분할하고 전처리·튜닝을 수행한다. 2019년 결과로 모델을 반복 조정하지 않는다.
- **누수 방지:** 종료일·종료연도처럼 미래 상태를 드러내는 값은 어느 연도 행에 들어 있더라도 제외한다. 다음 해 보험료·보장기간·의료 이용 정보도 제외한다. 결측 대체·인코딩 등은 개발용 학습 구간에서만 적합한다.
- **평가:** PR-AUC는 Average Precision으로 계산 방식을 명시하고, Recall@20%와 Lift@20%를 함께 확인한다. Recall@20%는 실제 이탈 대상 중 상위 20%에 포함된 비율, Lift@20%는 상위 20%의 이탈 비율을 전체 이탈 비율로 나눈 값이다.
- **추가 검증:** 같은 계약의 피보험자들이 독립적이지 않으므로 계약 단위 재표집으로 불확실성을 확인한다. 연도 간 동일 대상이 재등장하는 것은 기존 고객 예측 목적에 부합하지만, 계약 중복을 제거한 보조 평가도 구분해 보고한다.

데이터가 3개 연도에 한정되어 장기 변화나 최근 국내 시장에 대한 일반화에는 한계가 있다. 최종 결과가 단순 규칙보다 좋지 않더라도 그 결과와 한계를 그대로 정리한다.

## 7. 생성형 AI 활용 계획

Codex를 분석 질문 구체화, 공개 데이터 탐색, 전처리·검증 코드 작성, 시각화, 오류 해결, 결과 해석 검토와 보고서 초안 작성에 활용한다. 개인정보 원본 대신 컬럼 설명과 집계 정보를 제공한다.

이번 기획 단계에서는 AI가 제안한 자료의 실제 다운로드 가능 여부를 확인하고, 원자료를 실행 코드로 읽어 규모·식별자·연도 간 연결을 점검했다. AI가 제안한 분석 설계와 실제 확인한 사실은 구분해 기록한다. 이후에는 코드 실행 결과, 원자료 설명서와의 일치 여부, 수정 이유를 [AI 활용 기록](../docs/ai_usage.md)에 누적하고, 내가 설명할 수 있는 내용만 최종 보고서에 반영한다.
