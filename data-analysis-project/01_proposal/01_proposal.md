# 1차 데이터분석 프로젝트 기획

## 1. 프로젝트 주제

**건강보험 계약 이탈과 보험금 비용 특성 분석**

## 2. 해결하고 싶은 문제

생명보험 현업에서 계약 해지·실효 방지를 위한 유지관리 대상 선별 업무를 수행하고 있으며, 이를 논문 주제로 삼고 있다. [CSM(보험계약마진)](https://www.ifrs.org/supporting-implementation/supporting-materials-by-ifrs-standards/ifrs-17/key-terms/)은 미래 보험서비스에 대해 아직 손익으로 인식하지 않은 이익으로, 계약 유지 여부는 향후 이익 실현과 연결된다.

이번 프로젝트에서는 공개 건강보험 데이터로 계약 특성별 다음 해 이탈 비율을 분석한다. 이탈·유지 집단의 보험료 대비 보험금 비용을 비교하고, 보험금 비용 정보가 이탈 예측에 추가로 도움이 되는지 확인해 유지관리 업무에 활용하고자 한다.

스페인의 연간 갱신형 자료이므로 국내 장기 보장성 계약에 적용할 때는 계약 구조의 차이를 고려한다. CSM 평가자료와 상담·개입 이력이 없어 실제 CSM 변동액과 이탈 방어 효과는 분석하지 않는다.

## 3. 핵심 분석 질문

분석 대상은 기준연도 말 유지 중인 피보험 관계다. 기준연도 정보와 다음 해 상태를 연결하며, 다음 해 신규 가입자는 제외한다.

| 핵심 분석 질문 | 주요 변수 | 예상 분석 방법 |
|---|---|---|
| 가입 기간, 보험료, 상품 유형, 판매 채널에 따라 다음 해 이탈 비율은 어떻게 다른가? | 가입 기간, 보험료, 상품 유형, 판매 채널, 다음 해 이탈 여부 | 그룹별 비교, 시각화 |
| 다음 해 이탈 대상과 유지 대상은 기준연도 보험료 대비 보험금 비용 비율에서 어떤 차이가 있는가? | 기준연도 보험료·보험금 비용·보장 기간, 다음 해 이탈 여부 | 집단별 비용 비율 비교, 상품·가입 기간별 추가 확인 |
| 기본 계약 정보에 기준연도 보험금 비용 정보를 추가하면 다음 해 이탈 예측 성능이 개선되는가? | 가입 기간, 보험료, 상품 유형, 판매 채널, 기준연도 보험금 비용, 다음 해 이탈 여부 | 로지스틱 회귀·랜덤 포레스트의 기본·확장 모델 비교, 이후 연도 검증 |

첫 번째 질문은 이탈 특성, 두 번째는 이탈·유지 집단의 과거 비용 특성, 세 번째는 보험금 비용 정보의 추가 예측 가치를 확인한다.

보험료는 고객이 납부한 금액이고, 보험금 비용은 보험사가 의료비 보장을 위해 부담한 비용이다. 두 번째 질문의 비용 비율은 각 집단의 `기준연도 보험금 비용 합계 ÷ 기준연도 보험료 합계 × 100`으로 계산한다. 사업비와 미래 현금흐름 등이 반영되지 않으므로 전체 수익성이나 CSM으로 해석하지 않는다.

## 4. 데이터 확보 계획

| 항목 | 내용 |
|---|---|
| 데이터 출처 | Mendeley Data, *Dataset of health insurance portfolio*, Version 4 |
| 제공자 | Josep Lledó, Priscila Espinosa Adamez, Virgilio Perez Gimenez |
| 데이터 URL | [원자료 및 변수 설명서](https://data.mendeley.com/datasets/386vmj2tbk/4) · [DOI](https://doi.org/10.17632/386vmj2tbk.4) |
| 자료 범위 | 스페인 보험사의 익명화된 건강보험 자료, 2017~2019년 |
| 데이터 수집 방법 | 공개 Excel 원자료와 변수 설명서를 다운로드하고 파일 체크섬을 확인 |
| 데이터 규모 | 실제 확보 기준 228,711행·42열. 고유 `ID` 100,453개, 고유 `ID_policy` 45,162개 |
| 실제 확보 가능 여부 | 2026년 10월 4일 다운로드·로딩 및 연도 간 연결 확인 완료 |
| 이용조건 | CC BY 4.0. 출처·버전과 가공 내용을 기록 |

자료의 설계는 [관련 연구 논문](https://doi.org/10.1038/s41597-025-06372-z)을 참고했다. 원자료는 로컬에 보관하고, GitHub에는 출처·코드·집계 결과를 관리한다. 회사 고객정보는 사용하지 않으며 공개 자료의 익명 식별자도 재식별에 이용하지 않는다.

### 실제 데이터 확보 결과

| 기준연도 → 결과연도 | 기준연도 유지 대상 | 다음 해 상태 확인 | 다음 해 기록 미확인 |
|---|---:|---:|---:|
| 2017 → 2018 | 63,487 | 63,486 | 1 |
| 2018 → 2019 | 59,833 | 59,831 | 2 |

**결과 관찰:** `ID`와 `period` 조합의 중복은 0건이다. 대부분의 유지 대상을 다음 해 기록과 연결할 수 있으며, 일부 지역 관련 변수에는 결측이 있다.

**나의 해석과 판단:** 이전 연도 정보와 다음 해 상태를 연결할 수 있어 분석 질문에 답할 수 있는 자료로 판단했다. 다음 해 기록이 없는 3건은 이탈로 처리하지 않고 결과 미확인으로 구분한다. 종료일의 빈 값은 유지 상태를 의미할 수 있으므로 일괄 삭제하지 않는다.

확인 근거: [실행 코드](../docs/check_source_data.py), [데이터 구조·품질 확인 결과](../docs/data_feasibility.json), [수집 파일 및 체크섬](../data/source_manifest.json).

### 주요 컬럼 및 변수

한 행은 피보험 관계 1개의 연도별 기록이다. 한 계약에 여러 피보험자가 포함될 수 있으므로 행 수와 계약 수를 구분한다. `ID_insured`는 계약 내 순번으로, 단독 연결 키로 사용하지 않는다.

| 구분 | 주요 컬럼 | 의미 및 사용 계획 |
|---|---|---|
| 식별·연결 변수 | `ID`, `ID_policy`, `ID_insured`, `period` | 연도 간 연결과 계약 단위 검증. 예측 변수에서는 제외 |
| 종속변수 | 다음 해 `lapse` | 다음 해 이탈 여부 |
| 기본 모델 변수 | `seniority_insured`, `seniority_policy` | 피보험자 가입 기간, 계약 유지 기간 |
| 기본 모델 변수 | `premium` | 고객이 납부한 기준연도 연간 보험료, 유로 단위 |
| 기본 모델 변수 | `type_product`, `distribution_channel` | 상품 유형, 판매 채널 |
| 확장 모델 추가 변수 | `cost_claims_year` | 보험사가 부담한 기준연도 연간 보험금 비용, 유로 단위 |
| 검증용 변수 | 가입일·종료일, `exposure_time` | 상태와 날짜의 일치, 관측 시점 확인 |

변수 설명서에 따라 다음 해 `lapse=1` 또는 `3`을 이탈, `2`를 유지로 정의할 계획이다. `1`은 연중 종료, `3`은 연말 종료이며, 자발적 해지와 미납 실효를 구분하는 코드는 아니다. 2차 단계에서 날짜와 상태의 일치를 확인하고 두 종료 유형도 나누어 비교한다.

기본 모델은 가입 기간·보험료·상품·채널 정보를 사용하고, 확장 모델에는 `cost_claims_year`만 추가한다. 예측 변수는 기준연도까지 확인 가능한 값으로 제한하며, 보험금 비용의 확정 시점도 검토한다. 성별·의료서비스 이용 횟수·지역 사회경제 변수는 두 모델 모두 제외한다. 계약 변경 전후의 동일인 추적 여부가 불명확하므로 관계 종료를 보험사 전체에서의 고객 이탈로 단정하지 않는다.

## 5. 예상 분석 방법

| 단계 | 수행 내용 |
|---|---|
| 데이터 구조 및 품질 확인 | 결측치·중복·이상값·자료형, 보험료·보험금 비용의 범위, 상태와 날짜 확인 |
| 데이터 전처리 | 날짜·범주 정리, 연도별 연결, 결과 미확인 구분, 보장 기간 확인. 삭제·대체 기준 기록 |
| 탐색적 데이터 분석(EDA) | 계약 특성별 이탈 비율과 이탈·유지 집단의 기준연도 보험금 비용 비율 비교·시각화 |
| 분석·모델링 | 로지스틱 회귀와 랜덤 포레스트 각각에서 보험금 비용 추가 전·후의 예측 성능 비교 |
| 결과 검증 | 이후 연도 성능 차이, 금액 집계·보장 기간, 오류 사례와 한계 확인 |

### 결과 검증 계획

- **개발·평가 구분:** 2017년 정보와 2018년 결과로 개발하고, 2018년 정보와 2019년 결과로 최종 평가한다. 개발 데이터 내부는 계약 단위로 분할한다.
- **Data Leakage 확인:** 미래 종료일·종료연도와 다음 해 보험료·보험금 비용은 제외한다. 기준연도 보험금 비용이 예측 시점에 확정되어 있었는지 확인하며, 확인할 수 없으면 실무 사전 예측으로 일반화하지 않는다. 결측 대체와 인코딩은 학습 구간에서만 적합한다.
- **Baseline 및 모델 비교:** 기본 계약 정보만 사용한 모델을 Baseline으로 삼는다. 같은 알고리즘·설정·학습 및 평가 대상에서 보험금 비용만 추가해 비교하며, 최종 평가 결과에 맞춰 모델을 반복 조정하지 않는다.
- **주요 평가 지표:** Average Precision과 ROC-AUC로 이탈 대상 구분 성능을 비교한다. 이탈 비율이 연도별로 다를 수 있으므로 해당 연도의 이탈 비율을 함께 보고한다.
- **비용 비율 검증:** 보험료와 보험금 비용의 기준연도·대상을 일치시키고 중복 집계를 확인한다. 보험금 비용 0은 결측과 구분한다. 1년 전체 보장 대상만의 분석과 상품·가입 기간별 비교로 보장 기간과 구성 차이를 점검한다.
- **추가 확인:** 동일 평가 대상의 기본·확장 모델 성능 차이를 계약 단위 재표집으로 검토한다. 연도 간 같은 계약이 포함되는 경우와 제외한 경우도 구분한다.

결과 관찰과 해석을 구분해 작성한다. 변수 간 연관성을 원인으로 단정하지 않으며, 단일 보험사·3개 연도 자료의 한계를 밝힌다. 집단 간 차이가 없거나 보험금 비용 추가로 예측 성능이 개선되지 않아도 결과를 그대로 보고한다.

## 6. 생성형 AI 활용 계획

Codex를 분석 질문 구체화, 데이터 탐색, 전처리·EDA 코드 작성, 오류 해결, 결과 해석 검토와 보고서 작성에 활용한다. 개인정보 원본 대신 변수 설명과 집계 결과를 제공한다.

기획 단계에서는 Codex가 작성한 코드를 실행해 데이터 확보 여부와 구조를 확인했다. 이후에도 AI의 제안과 실행 결과를 구분하고, 보험료·보험금 비용의 정의와 계산 기준, 누수 여부를 검증한다. 활용 내용과 수정 근거는 [생성형 AI 활용 및 검증 기록](../docs/ai_usage.md)에 남긴다.

| 단계 | 일정 | 주요 내용 및 산출물 |
|---|---|---|

| 2차 — 데이터 확보·전처리·EDA | 10월 말 예정 | 전처리 기준, 이탈 특성·보험금 비용 비교, 주요 시각화, 1차 피드백 반영 |
| 3차 — 본 분석·모델링·검증 | 11월 말 예정 | 기본·확장 모델 비교, 이후 연도 평가, 성능 차이와 한계 검증 |
| 4차 — 프로젝트 최종 완료 | 12월 말 예정 | 최종 Notebook·분석 보고서, 핵심 인사이트, 한계 및 회고 |

2~4차 일정은 추후 공지에 따른다. 각 단계의 변경 사항을 GitHub에 누적하고 실행·재현 방법을 기록한다. 가능하면 Streamlit으로 집계 결과를 전달한다.
