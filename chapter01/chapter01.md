## 1. 원래 업무 질문

### 내가 선택한 막연한 질문

> 요즘 재구매하는 고객이 줄어든 것 같다.

### 왜 이 질문이 모호하다고 생각했는가?

- 대상: 어떤 주문 상태의 고객인지 알 수 없습니다.
- 기간: 언제부터 언제까지인지 정해지지 않았습니다.
- 기준: 재구매를 몇 회 이상으로 볼지 불분명합니다.
- 비교 방법: 월별로 볼지, 이전 기간과 비교할지 알 수 없습니다.
- 분석 목적: 결과를 어디에 활용할지 정해지지 않았습니다.

### 분석 가능한 질문으로 다시 작성

> 최근 6개월 동안 `completed` 주문 고객 중 2회 이상 구매한 고객의 비율은 월별로 어떻게 변했는가?

재구매 고객 비율의 변화를 확인하면 고객 유지 활동이 필요한 시점을 찾는 데 도움이 됩니다.

## 3. LLM에게 분석 질문 후보 요청

### 사용 목적

온라인 쇼핑몰 데이터로 확인할 수 있는 분석 질문 후보를 얻기 위해 사용했습니다.

### 사용한 Prompt

```text
온라인 쇼핑몰 데이터 분석을 준비하고 있습니다.

데이터는 다음 4개 파일로 구성됩니다.
- customers: 고객 정보
- products: 상품 정보
- orders: 주문 정보
- order_items: 주문 상세 정보

목적은 completed 주문 기준 금액과 구매 패턴을 이해하는 것입니다.
초보 데이터 분석자가 먼저 확인할 질문 5개를 제안해 주세요.
각 질문마다 필요한 파일과 컬럼 후보도 적어 주세요.
원인을 단정하지 말고 현재 데이터로 확인 가능한 질문만 제안해 주세요.
```

### LLM 답변 요약

1. 월별 `completed` 주문 금액 변화
2. 카테고리별 `completed` 주문 금액 차이
3. 고객별 구매 금액 분포
4. 주문 수와 주문당 평균 금액 변화
5. 기간별 취소 주문 비율

### 결과 관찰

LLM은 기간, 상품, 고객과 주문 상태를 기준으로 질문을 제안했습니다. 질문별로 필요한 파일과 컬럼 후보도 함께 제시했습니다.

### 나의 해석과 판단

질문 후보를 빠르게 넓히는 데 도움이 되었습니다. 다만 제안된 컬럼과 계산 가능 여부는 실제 데이터로 확인해야 합니다.

### 업무·분석적 의미

분석을 시작할 때 놓칠 수 있는 관점을 확인하고 질문 후보를 정리하는 데 활용할 수 있습니다.

### 한계와 추가 확인 사항

LLM은 데이터의 실제 값과 품질을 확인하지 못하므로 컬럼, 결측값과 계산 범위를 별도로 검증해야 합니다.

## 4. LLM 제안 검증

| 검증 항목 | 확인 내용 |
| --- | --- |
| 선택한 LLM 제안 | 월별 재구매 고객 비율을 확인한다. |
| 필요한 파일 | `orders.csv` |
| 필요한 컬럼 | `customer_id`, `order_date`, `order_status`, `order_id` |
| 계산 범위 | 최근 6개월의 `completed` 주문 |
| 실제 데이터 확인 필요 여부 | 컬럼 존재, 날짜형, 결측값과 상태값 확인 필요 |
| 원인 단정 여부 | 비율 변화만 확인하고 원인은 단정하지 않음 |
| 최종 판단 | 수정 후 사용 |

### 내가 수정한 내용

분석 기간을 최근 6개월로 정하고, 재구매 고객을 `completed` 주문 2회 이상인 고객으로 정의했습니다.

### 결과 관찰

LLM 제안에는 기간과 재구매 기준이 없어 그대로 계산하기 어려웠습니다.

### 나의 해석과 판단

필요한 기준을 추가하면 현재 데이터로 확인할 수 있으므로 수정 후 사용하기로 했습니다.

### 업무·분석적 의미

LLM 제안을 검증하지 않으면 사람마다 다른 기준으로 계산해 결과가 달라질 수 있습니다.

### 한계와 추가 확인 사항

재구매를 2회 이상으로 정한 기준은 업무 상황에 따라 달라질 수 있습니다.

## 8. Chapter 01 최종 해석

### 이번 장에서 가장 중요하다고 생각한 내용

데이터 분석은 코드보다 질문을 먼저 구체화해야 한다는 점이 가장 중요했습니다. LLM은 질문과 코드의 초안을 만드는 데 도움이 되지만, 실제 데이터와 맞는지는 사람이 확인해야 합니다. 실행 결과만 제시하지 않고 관찰, 판단과 한계를 함께 작성해야 분석 결과를 올바르게 전달할 수 있습니다.

### LLM을 데이터 분석에 사용할 때 가장 조심해야 할 점

존재하지 않는 컬럼이나 확인되지 않은 원인을 사실처럼 사용할 수 있다는 점입니다. 실제 데이터와 계산 기준을 확인하고 개인정보와 Secret을 입력하지 않아야 합니다.

### 사람과 LLM의 역할 차이

| 항목 | LLM이 도울 수 있는 부분 | 사람이 책임져야 하는 부분 |
| --- | --- | --- |
| 질문 정의 | 질문 후보와 표현 제안 | 업무 목적과 범위 결정 |
| 데이터 확인 | 필요한 컬럼 후보 제안 | 실제 파일과 컬럼 검증 |
| 코드 작성 | 코드 초안 작성 | 실행과 오류 확인 |
| 결과 해석 | 해석 방향 제안 | 관찰과 추측 구분 |
| 최종 판단 | 참고 의견 제공 | 사용·수정·보류 결정 |
